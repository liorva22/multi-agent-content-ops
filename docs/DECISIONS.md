# Design decisions

| # | Decision | Alternatives | Why |
|---|----------|--------------|-----|
| 1 | **Hand-rolled state machine instead of LangGraph** | LangGraph `StateGraph` with a conditional edge | The graph is four nodes in a line plus one back-edge (fact-check → write). The `while` loop with an explicit `step` variable is ~60 lines that read top to bottom, has zero framework dependencies, and is trivial to test (`log` is a plain callback). What LangGraph would add here: checkpointing, which the per-step Postgres log already provides for observability; parallel branches and human-in-the-loop interrupts, which aren't needed yet. **Revisit** if the flow gains parallel research agents, tool-using loops, or resumable human approvals. |
| 2 | **Rollback = discard the draft, keep the research, re-prompt the writer with the fact-checker's issues** | Patch the draft in place; restart from research | Research is the expensive, stable part. Patching in place tends to leave the bad claim reworded rather than removed. Re-writing from facts plus explicit issues is cleaner and is bounded by `max_write_attempts`. |
| 3 | **Escalate to `needs_review` when retries run out**, instead of publishing anyway | Publish with a warning; fail silently | A post that failed fact-checking three times needs a human. The state is explicit and visible on the dashboard. |
| 4 | **Fact-checker = LLM + deterministic number verification** (every number in the draft must appear in the PRD or research notes) | LLM only | Invented statistics are the most damaging hallucination in marketing copy, and they're cheap to catch exactly. The LLM covers the rest (exaggerations, wrong attributions). |
| 5 | **Model per agent by difficulty**: Sonnet researches and writes, Opus fact-checks, Haiku polishes | One model everywhere | Fact-checking is the step where an error is most expensive, so it gets the strongest model. Polishing is a constrained edit, so it gets the cheapest. Config-driven (`config.yaml`). |
| 6 | **One `steps` row per transition**, with tokens, cost, latency, attempt, status, full output, and detail JSON | Log only final results; use a tracing SaaS | Every artifact on the timeline is reconstructible from SQL, with no vendor dependency. Retries are just rows with `attempt > 1`. |
| 7 | **Rubric: 7 deterministic checks + an LLM judge (live only)** | LLM judge only | Format and length rules don't need an LLM, and deterministic checks are free and stable. Mock mode reports the judge as "not run" rather than inventing scores. |
| 8 | **Scripted mock hallucinations** (`MockAgents.SCRIPTED_HALLUCINATIONS`, per PRD title) | Random; hash-based | An earlier hash-based version happened to give 0 hallucinations for all three PRDs, which hid the rollback path. An explicit table is honest about what's scripted, and it guarantees the demo exercises 0, 1, and 2 retries. |
| 9 | **FastAPI `BackgroundTasks` for API-triggered runs** | A queue + worker, as in project 02 | Runs are short, and the CLI and compose `seed` job are the main entry points. Each background run opens its own DB connection. A queue is the upgrade once runs get long or concurrent. |
| 10 | **Streaming calls with `get_final_message()`** | Non-streaming `create` | Long blog posts plus thinking can exceed non-streaming HTTP timeouts. |
